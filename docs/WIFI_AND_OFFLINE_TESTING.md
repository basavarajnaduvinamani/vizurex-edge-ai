# Phone testing: Wi-Fi and experimental offline mode

## Choose a mode

| Mode | Where inference runs | Supported client | What has been checked |
|---|---|---|---|
| Local/USB | Laptop | Browser or Android APK | Automated API/model tests |
| Private Wi-Fi | Laptop | iPhone Safari, Android browser or APK | Host, origin and session-key tests; phone-layout check |
| Experimental on-device | Android CPU | Updated Android APK | APK compilation, manifest tests and laptop ONNX tensor parity; no real Android inference test yet |

No Meta SDK or glasses are involved. No public website or native iOS app is provided.

## Private Wi-Fi

Use only trusted Wi-Fi and non-sensitive benchmark images. The prototype uses
HTTP, not encrypted HTTPS. A session key prevents unauthenticated API use but
does not protect traffic from interception on an untrusted network. No firewall
settings, router forwarding or public hosting have been configured.

1. Put laptop and phone on the same trusted Wi-Fi. Find the laptop's Wi-Fi IPv4
   address in Windows network settings. Do not choose a VPN or unrelated adapter.
2. From `development`, run `powershell -ExecutionPolicy Bypass -File scripts/start_wifi.ps1 -LaptopIPv4 YOUR_PRIVATE_IPV4`.
3. Open the displayed URL in Safari/Chrome. Enter the session key shown in the
   laptop terminal and press **Apply key**. It is kept only in the browser tab's
   memory. The key is not included in the URL or inspection log.
4. In the Android APK, select **Laptop backend**, set the same base URL and enter
   the session key. The app does not save the key.
5. Inspect the known good and defective benchmark images for the selected category.

Stopping/restarting the Wi-Fi script rotates the key. Some campus/guest networks
isolate devices; in that case, use Android USB testing instead. Windows may also
block inbound access. Do not disable the firewall broadly or open a public port.
Any firewall access decision should be reviewed separately for the trusted private
network and specific service.

The Wi-Fi script binds to the selected private address. The local script binds
to 127.0.0.1. These are alternative service modes, not a claim that both addresses
are served simultaneously. Run `scripts/start_local.ps1` to return to local/USB.

## Experimental Android-only inference

This is implemented but not device-qualified. Start with one category and a
benchmark image, not an arbitrary manufactured item.

1. Install the latest `android-companion/app/build/outputs/apk/debug/app-debug.apk`.
2. Copy a trusted bundle from `artifacts/portable-candidate/v2/CATEGORY/` to the
   device's Downloads folder. For bottle, the file is `visurex-bottle-mobile.zip`.
   The category ZIPs are about 81 MB each in decimal units. The universal debug
   APK is about 80 MB because it includes native ONNX Runtime libraries.
3. Select **Experimental on-device CPU** in the app.
4. Press **Import trusted portable model ZIP** and select the ZIP. It must match
   the category you intend to inspect. Models are not embedded in the APK.
5. Choose a benchmark image and run inspection. This code path does not submit
   the image to the laptop API. You can test without the laptop connection after
   importing the model. Model resources last for the current activity session;
   rotation/recreation currently requires importing the model again.

The importer checks archive names/size, metadata, category and model checksum.
Hashes detect corruption, not a trustworthy publisher. Only import bundles
generated by this project from trusted source models. The app does not accept
arbitrary online model downloads.

Offline mode displays an image-level score and processed crop. The laptop's
capture-quality policy and smoothed heatmaps are not implemented in this mode.
Android bitmap resizing differs from the Pillow reference, so matching input
tensor results on the laptop does not prove matching Android image results.
EXIF orientation handling is included. Actual device memory use, model import,
latency, camera behaviour, rotation and score agreement remain acceptance tests.

## Current portable-model evidence

| Category | Test images | ONNX graph size (bytes) | Largest score difference from rounded reference |
|---|---:|---:|---:|
| Bottle | 83 | 101,630,247 | 0.00006566 |
| Grid | 78 | 102,161,549 | 0.00005992 |
| Transistor | 100 | 101,665,667 | 0.00006817 |

All decisions matched. The fixed-shape graph takes a preprocessed float32
`[1,3,224,224]` tensor and returns an image score plus raw 28x28 patch distances.
It is not quantised and does not output confidence probabilities. Graph size is
smaller than the full backbone bundle because unused later layers are omitted.

The initial transistor candidate missed the reference's zero-floor normalisation
for one image. That failed candidate was preserved and not packaged. Version 2
restores the same score floor and passed all categories. No benchmark data was
used to retrain the model or retune its decision threshold during conversion.

Reproduction: install `requirements-portable-export.txt`, run
`scripts/export_portable_candidate.py --category CATEGORY --version NEWVERSION`,
then `scripts/package_portable_mobile.py --category CATEGORY --version NEWVERSION`.
Completed output paths are not overwritten. Verification is CPU inference on
the laptop, not Android hardware or industrial deployment evidence.
